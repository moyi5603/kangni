# 活动模块 · 批量操作交互说明

适用角色：活动运营 / 行政人员，在后台列表对多条记录做同一动作。  
范围：活动管理、奖品发放、满意度调查、报名管理、评论管理、精彩瞬间管理。  
审批记录为流水账，不提供批量操作。

---

## 1. 通用规则

### 1.1 何时出现

- 表格左侧勾选列始终展示。
- **未勾选**：不展示批量栏。页面主按钮（新建）保持在表格上方工具栏。
- **勾选 ≥ 1 条**：表格与工具栏之间出现批量栏，浅蓝底，与查询区、表格区分开。
- 批量栏左侧文案：`已选择 N 项（含其他页）`。本模块允许跨页勾选，必须在文案里写明，避免用户以为只选了当前页。
- 换页、改每页条数、排序：已勾选记录保留。
- 点「查询 / 重置」、离开当前列表页：清空勾选。筛选结果变了，旧勾选不再可信。

### 1.2 栏内按钮顺序

从左到右：**主批量动作 → 次批量动作 → 取消选择**。

- 主按钮最多一个。活动管理「批量发布」、报名「批量通过」用默认按钮（非 Primary），避免和页面「新建」抢主色。
- 「取消选择」永远在最右，次按钮，无确认，立刻清空勾选，数据不变。

### 1.3 执行原则：只处理符合条件的记录

批量不是全成功或全失败。系统按规则筛出可执行项，跳过其余，一次提交。

| 结果 | 行为 |
| --- | --- |
| 全部可执行 | 执行；成功提示条数；清空勾选 |
| 部分可执行 | 只改可执行项；成功提示里拆开「成功 N / 跳过 M 及原因」；**勾选保留跳过项**，方便补操作或核对 |
| 全部不可执行 | 不改数据；info 提示原因；勾选保留 |

服务端未返回前，对应按钮进入 loading，禁止连点。成功提示必须等变更完成后再出。

### 1.4 确认强度

批量会改多条状态，一律二次确认。需要补参数时用表单弹窗，不再叠一层确认。

| 强度 | 承载 | 用在 |
| --- | --- | --- |
| 高 | Modal 确认，标题含对象数量，正文说明影响和跳过规则 | 发布、撤销、发放、开始收集、通过、驳回、删除 |
| 参数 | Modal 表单，标题含已选数量 | 设置分类 |
| 无 | 直接生效 | 取消选择 |

确认 Footer 固定：**确认（左，主按钮）+ 取消（右）**。  
标题模板：`确认{动作}已选 N 个{对象}？`  
正文必须写清：对谁生效、跳过谁、对外可见性或不可逆影响。

### 1.5 与行操作的关系

行操作与批量操作业务规则一致，只是范围是 1 条。行上不可用的动作（如未审批通过不能发布）在批量里同样跳过，不报错中断整批。

## 2. 分页面说明

### 2.1 活动管理

勾选后动作：**批量发布**、**撤销**、**设置分类**、取消选择。无批量审核。

行操作第三格按状态切换：待提交/已驳回 → 提交审批；待审核 → 审核；已发布 → 撤销；已通过/无需审核且未发布 → 发布；其余禁用发布。详情页待审核时主按钮为审核。

**审核（行/详情）**

- 可执行：`审核状态 = 待审核`。
- 弹窗填意见。通过可不填；驳回必填。
- 通过：审核状态 → 已通过。驳回：审核状态 → 已驳回。均写入审批记录。

**批量发布**

**批量发布**

- 可执行：`发布状态 = 未发布` 且 `审核状态 ∈ {已通过, 无需审核}`。
- 结果：发布状态 → 已发布；无发布时间则写入当前时间，已有发布时间不覆盖。
- 跳过：已发布；未发布但待审核 / 已驳回。
- 确认正文：`仅未发布且审核为已通过或无需审核的活动会被发布。其余保持不变。撤销后员工端将可见这些活动。`
- 成功例：`已发布 3 个活动，1 个本为已发布，2 个因未审批通过无法发布`

**撤销**

- 可执行：`发布状态 = 已发布`。
- 结果：发布状态 → 未发布，发布时间清空。
- 跳过：未发布。
- 确认正文：`撤销后活动不再对员工可见。仅已发布活动会被撤销。`
- 高影响：对外下线，必须 Modal。

**设置分类**

- 可执行：全部已选活动。
- 弹窗标题：`设置分类 · 已选 N 项`。
- 字段：分类，必填，下拉，选项与新建/编辑活动一致。
- 说明：`将覆盖已选活动的当前分类，保存后立即生效。`
- 确认后立刻改分类，不清发布/审核状态。成功：`已将 N 个活动设为「{分类}」`，然后清空勾选。

### 2.2 奖品发放

无勾选列、无批量、无行删除。发放记录只增不删。

列表一行一个人一次发放。类型选项现仅「勋章」。

- 发放：仅 `发布状态 = 已发布` 且 `活动状态 = 已结束`。抽屉选类型（现仅勋章）、勋章（下拉搜索）和对象。提交即写入人员记录。已获同一勋章的人跳过。未结束或未发布时「发放奖励」禁用。

### 2.3 满意度调查

勾选后动作：**批量开始收集**、取消选择。

- 可执行：`状态 = 草稿`。
- 结果：草稿 → 收集中。收集中、已结束跳过。
- 确认正文：`仅草稿问卷会进入收集中，员工可开始填写。已在收集或已结束的问卷保持不变。`
- 成功：`已开始收集 N 份问卷`；部分跳过时写明条数。

### 2.4 报名管理

勾选后动作：**批量通过**、**批量驳回**、取消选择。通过在左（主批量），驳回在右。

- 可执行：`状态 = 待审核`。已通过、已驳回、已取消跳过。
- 通过：待审核 → 已通过。确认正文：`仅待审核记录会被通过。`
- 驳回：待审核 → 已驳回。确认正文：`仅待审核记录会被驳回，报名人将无法参加该活动。`
- 无可执行：`已选报名均不是待审核状态`
- 同一批不能同时通过又驳回；一次确认只走一个动作。
- 行操作：待审核显示「通过」「驳回」「删除」；其余只显示「删除」。驳回、删除需确认。

### 2.5 评论管理

勾选后动作：**批量删除**、取消选择。评论无需审核，不提供隐藏、查看、编辑。

- 可执行：已选全部评论。
- 结果：从列表移除，员工端不再展示，无法恢复。
- 确认正文：`删除后员工端不再展示这些评论，且无法恢复。`
- 行操作同样只有「删除」，确认标题含评论人。

### 2.6 精彩瞬间管理

勾选后动作：**批量通过**、**批量驳回**、取消选择。无新建、无批量删除。

- 可执行：`状态 = 待审核`。
- 通过结果：待审核 → 已通过，员工端可见。已通过、已驳回跳过。
- 驳回：待审核 → 已驳回，原因必填且共用一条。作者可在 C 端改后再提。
- 确认通过正文：`待审核将变为已通过，员工端可见。其他状态保持不变。`
- 删除只走行操作或详情评论树，不可恢复。

### 2.7 审批记录

无勾选列、无查询筛选、无行操作。数据量小，直接列表查看，不改历史。

## 3. 异常与反馈

| 场景 | 表现 |
| --- | --- |
| 成功（全量） | Message 成功：`已{动作} N 个{对象}`，清空勾选 |
| 成功（部分） | Message 成功，拆开成功/跳过原因；勾选留跳过项 |
| 全部跳过 | Message info，说明为何都不能做；勾选保留 |
| 请求失败 | Message 错误：发生了什么、数据未改、可重试；勾选保留 |
| 无权限 | 对应批量按钮不展示；直接打接口仍失败并提示无权限 |
| 提交中 | 按钮 loading，禁止再点其他批量动作 |
| 空列表 / 筛选无结果 | 不展示批量栏（无从勾选） |

错误不静默吞掉。跳过不是失败，用成功或 info，不弹 error。

## 4. 验收场景

假设运营在活动管理列表勾选 5 条：2 条未发布且已通过、1 条已发布、2 条待审核。  
当确认批量发布。  
那么仅 2 条变为已发布；提示含成功 2、本为已发布 1、未审批通过 2；勾选剩余 2 条待审核。

假设运营勾选 3 条已发布活动。  
当确认撤销。  
那么 3 条变为未发布、发布时间清空；员工端不可见；勾选清空。

假设运营勾选跨两页共 4 条活动。  
当改到第 2 页。  
那么批量栏仍显示已选择 4 项（含其他页）；第 1 页勾选不丢。

假设运营在奖品发放页。  
当查看表格。  
那么没有勾选列、批量栏和删除。

假设运营勾选 3 条待审核报名后点批量驳回。  
当确认。  
那么 3 条变为已驳回；提示已驳回 3 条报名。

假设运营在审批记录页。  
当查看表格。  
那么没有勾选列和批量栏。

## 5. 不做的事

- 不提供「全选所有查询结果」（跨全部页全选）。当前只支持「当前页全选 + 跨页勾选保留」。
- 不在未勾选时用禁用按钮占位批量栏。
- 批量不弹复杂表单（设置分类除外）。
- 不把删除做成批量（奖品发放、审批记录无删除；评论可批量删除）。
