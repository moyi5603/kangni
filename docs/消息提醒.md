# 消息提醒

按应用列出当前原型里会触达人的消息。范围是应用切换器中的业务应用，另加评优（荣誉引擎有演示消息，后台入口已隐藏）。

状态含义：

- **有文案**：标题、正文或模板已写在配置或演示数据里。
- **仅开关**：页面有触发说明，没有文案、图片、跳转，也没有发送实现。
- **演示**：C 端写死一条样例，不随后台配置变化。
- **无消息**：该应用没有消息触发。

原型没有统一消息中心。除下面标明的演示会话外，开关保存后不会真正发出去。

补充字段：发送方、时机、变量、频控、默认开关。这些是现有配置里能确定的，没有的标「未定义」。

## 员工关怀

消息内容在关怀模板里配。规则决定何时发给谁，并关联一个或多个模板。多模板时发哪一条，未定义。

模板两类封面：

- 祝福消息封面、提醒消息封面：横图，示例比例 1068×455。
- 贺卡底图：竖图，示例 360×640。点开贺卡后展示，不是消息列表上的封面。

### 祝福消息
根据规则如果隐藏了高管，不给任何人发提醒

| 项 | 内容 |
| --- | --- |
| 触发 | 规则命中。个人：生日（阳历或阴历，跟员工档案「生日提醒」）、入职周年、入党纪念日。固定日期：所选节日当天，或「其他」的每年月日、一次性日期。|
| 接收人 | 命中该场景的员工。规则数据上有范围（部门或指定员工），当前规则表单没有范围控件。 |
| 时机 | 非事件：前一天或当天 + 时刻，按规则中的配置。|
| 文案 | 模板「标题」+「副标题」。标题最多 64 字，副标题最多 120 字。 |
| 图片 | 祝福消息封面。 |
| 跳转 | 跳转到对应模版贺卡的落地页。 |
| 发送方 | 系统。关怀记录发送人写「系统」。 |



### 提醒消息（同事祝福邀请）

只在个人关怀（生日、周年、入党），且规则打开「开启同事祝福」，其他关怀无此提醒。根据规则如果隐藏了高管，不给任何人发提醒

| 项 | 内容 |
| --- | --- |
| 触发 | 同上个人场景（生日、周年、入党），时间单独配。 |
| 接收人 | 同事范围二选一：员工所在末级部门，或其所在一级部门下的人。排除本人。 |
| 时机 | 跟据规则配置 |
| 文案 | 模板「提醒消息」标题 + 副标题。字数上限同祝福消息。 |
| 图片 | 提醒消息封面。 |
| 跳转 | 跳转到关怀页面 |
| 发送方 | 系统。 |


### 同事写给本人的祝福

员工从提醒进入后发送。关怀设置里的表情会带入默认文案，员工可改。

| 项 | 内容 |
| --- | --- |
| 触发 | 同事提交祝福。 |
| 接收人 | 被关怀的员工。 |
| 文案 | 员工自写。表情默认文案见下表。 |
| 图片 | 所选表情图。 |
| 跳转 | H5转到关怀记录页（无的关怀）并定位到已收到的tab页；PC跳转到个人中心并定位到我的关怀tab页 |
| 发送方 | 同事本人。记录来源为「用户关怀」，积分 0。 |

## 即时激励

C 端有一条演示会话，后台发放不会按记录生成消息。

| 项 | 内容 |
| --- | --- |
| 触发 | 勋章已发放给接收人。公司表彰立即触发，同事认可未开启审核立即触发，开启审核审核通过后触发 |
| 接收人 | 被认可人。 |
| 时机 | 真实发放时间触发。 |
| 文案 | 标题「你收到一枚新勋章」。同事认可副文案，「{发放人}给你发了一枚「勋章名称」勋章，+xxx积分。公司表彰副文案，「公司给你发了一枚「勋章名称」勋章，+xxx积分。 |
| 图片 | 勋章图。 |
| 跳转 | 点卡片进勋章详情。详情主文案未读是「恭喜你获得新勋章」，已读是「已获得勋章」，并展示勋章说明、获得理由、发放人、获得时间、「已记入个人荣誉档案」。 |
| 发送方 | 即时激励助手（官方）。卡片上同时露出发放人。 |
| 其他 | 待审核、驳回、撤回没有消息。风控只在发放详情和审核页提示，不发消息。公司表彰免审核，发放后是否发同一条勋章消息，未定义。 |

### 报名审批人缺失

业务约定发给活动创建人和活动管理员。原型只把句子记在该条报名的「审批通知」里，后台通过节点时用提示条打出来。没有消息封面，没有跳转。活动表单有创建人、发起人，没有「活动管理员」字段。

会发的文案：

- `第 N 节点审批人缺失（{姓名}已离职 / 已停用 / 已冻结 / 已离职办理中，或{姓名}不存在），该节点已自动跳过`
- `第 N 节点部门不存在，负责人缺失，该节点已自动跳过`
- `第 N 节点「{部门}」本部门负责人缺失，该节点已自动跳过`
- `第 N 节点「{部门}」上级部门负责人缺失，该节点已自动跳过`
- 这次跳过导致报名通过时，末尾再加：`审批流已完成，报名已通过`

不发缺失通知的情况：节点上还剩其他在职审批人；审批人与报名人或上一审批人是同一人（只记跳过日志）；已经到组织顶层（只记日志）；在职但调岗或不再是部门负责人（只换当前待办，不发）。

待审核时当前审批人、通过、驳回，都没有发给审批人或报名人的消息文案。

## 论坛

没有推送。被指派回复、且本人还没回复时，帖子列表和详情上有一条状态条，不是消息。

| 项 | 内容 |
| --- | --- |
| 触发 | 后台把当前用户指派为该帖回复人，且该人尚未回复。 |
| 接收人 | 被指派的人。可多人。 |
| 文案 | 「需要你回复」，按钮「我来回复」。PC 侧栏标题是「待你回复」。 |
| 图片 | 无。 |
| 跳转 | 就在该帖上，没有单独链接。 |
| 其他 | 取消指派后这条消失。论坛本身没有响应时效；响应时效只在信箱。 |

## 评优

后台评优应用没有消息配置。下面是荣誉引擎 C 端写死的演示，文案带具体活动名，不会按新活动生成。

铃铛一条和会话一条经常是同一事件的两种展示。图片都没有，用类型图标。跳转是应用内页面，不是 URL。

| 触发 | 接收人 | 文案 | 跳转 |
| --- | --- | --- | --- |
| 活动发布，向提名人发邀请 | 配置的提名人。演示写「HR 邀请您参与」 | 标题「提名邀请」。正文：「您好，{姓名}！{邀请人} 邀请您参与「{活动}」评优活动，为您认为最优秀的创新项目提名。」附截止时间、已提名数。按钮「立即提名」 | 活动详情 |
| 提名截止前 | 提名人。演示为还剩 3 天 | 标题「截止提醒」。「「{活动}」提名还剩 3 天截止，目前已有 N 个项目完成提名，快去提名吧！」 | 活动详情 |
| 员工提交提名成功 | 提交人 | 标题「提名成功」。「您已成功提名「{项目}」，感谢您的参与！活动进入投票阶段后，我会第一时间通知您。」 | 无按钮 |
| 进入投票 | 演示为全体员工 | 标题「投票开始」。受众「致全体员工」。「「{活动}」提名已结束，正式进入投票阶段！共 N 个项目入围……」按钮「去投票」 | 活动详情 |
| 投票结束并公示 | 演示为全体员工 | 标题「投票结束」。「「{活动}」投票已结束……获奖结果已正式揭晓……」附最高票、获奖人。按钮「查看结果」 | 结果页 |
| 投票结束待复核 | HR | 铃铛标题「投票结束」。「「{活动}」投票已结束，请进行结果复核」 | 活动详情，角色 HR |
| 有人提交名单待审 | HR | 铃铛标题「提报审核」。「有人提报了「{活动}」的名单，请尽快审核」 | 活动详情，角色 HR |
| 结果揭晓 | 员工 | 铃铛标题「结果公示」。「「{活动}」获奖结果已揭晓，冠军：{姓名}」 | 结果页 |

提名成功后，机器人会再问要不要 AI 写提名，这是会话里的追问，不是另一条业务通知。

演示消息列表里还有「年假审批通过」「公司公告」，不属于评优触发。

## 以下应用没有消息

投票、课程、技能大赛、考试练习、抽奖、勋章、打卡。

打卡文化打卡可打开「可分享」：用户把打卡成果分享到朋友圈或好友，要配齐分享图。这是用户主动分享，不是系统消息。

勋章应用只管理勋章主数据。员工收到勋章的那条消息在即时激励里。
