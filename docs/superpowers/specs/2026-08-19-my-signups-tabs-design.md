# 我的报名 Tab 分组

**日期：** 2026-08-19  
**状态：** 已确认，待实现  
**范围：** H5 / PC「我的报名」列表从上下两段改成三个 tab。首页「我的活动」预览、发现活动、详情、后台不改。  
**关联：** `docs/superpowers/specs/2026-08-19-signup-status-row-and-demo-data-design.md`

## 背景与目标

「我的报名」现在上下堆「待参加」和「已结束」。待参加里还混着未开始和进行中，一屏挤、结束的要往下滚。改成 tab，并把进行中单独成组。

## 方案

有报名记录时，列表上方固定三个 pill tab（样式对齐发现活动分类 tab，选中用主色）：

`待参加` | `进行中` | `已结束`

不要数量角标。默认选中 **待参加**。点 tab 只换当前列表，不改 hash。空 tab 仍显示 tab 栏，列表处一句空文案，不自动跳到有数据的 tab。

完全没有报名时，保持现有整页空态（还没有报名活动 + 去看看活动），不出现 tab。

## 分组规则

在 `clientVisibleActivities` 关联之后：

| Tab | 条件 |
|---|---|
| 待参加 | 有已发布活动，且 `activityStatus === '未开始'` |
| 进行中 | 有已发布活动，且 `activityStatus === '进行中'` |
| 已结束 | 无关联活动（失效），或 `activityStatus === '已结束'` |

排序仍按 `createdAt` 倒序。卡片 UI（封面、状态行、报名类型、日期地点）不变。

首页「我的活动」预览继续用「未开始 + 进行中」合计，上限 2，不按三个 tab 拆。`groupClientSignups` 可增加 `waiting` / `ongoing` 字段，但必须保留现有 `upcoming`（未开始+进行中）给首页，避免预览规则被带崩。

## 空文案

| Tab | 文案 |
|---|---|
| 待参加 | 暂无待参加活动 |
| 进行中 | 暂无进行中活动 |
| 已结束 | 暂无已结束活动 |

## 表面

H5 `#/c/h5/my`、PC `#/c/pc/my` 同一套规则。PC 顶栏仍是「员工活动」+ 返回列表。H5 顶栏仍是「我的报名」。

Tab 交互：H5 用 `role="group"` + `aria-pressed`（与发现活动分类一致）。PC 可同样用 `aria-pressed`，或保持现有 PC 分类 `role="tab"` 习惯，但三个 tab 必须有选中态和可点区域 ≥ 44px。

## 测试

- 无报名：无 tab，仍是整页空态。
- `loadDemoSignups()` 后默认 tab 为待参加：可见年度体检、中秋晚会；不见训练营（进行中）、不见春季开放日（已结束）；有三个 tab 文案。
- 切到进行中：可见训练营；不见体检、晚会、开放日。
- 切到已结束：可见春季开放日；不见训练营、体检、晚会。
- 单测分组：未开始进 waiting，进行中进 ongoing，已结束和失效进 ended；`upcoming` 仍含未开始+进行中。
- 现有失效卡、封面、状态行测试在对应 tab 的列表里继续成立（`SignupGroup` 仍可按当前 tab 的 items 渲染）。

## 不做

- Tab 不带数字。
- 不改首页预览条数和「查看全部」规则。
- 不改发现活动、详情、后台。
- 不把三个分组写进 URL。
