# 精彩瞬间：C 端投稿 + 后台审核

**状态：** 已定稿  
**日期：** 2026-08-18  
**范围：** 康尼2 活动「精彩瞬间」。C 端图文/视频投稿、点赞评论回复；后台按规则审核、删除瞬间与评论回复。去掉后台新建。

## 背景

现网后台「精彩瞬间管理」是运营自己建图片/视频瞬间，状态为待发布/已发布。规则设置已有「开启精彩瞬间审核」，此前只存开关。C 端活动页没有瞬间。

本轮改成员工投稿、按类型审核、通过后互动。活动「评论管理」仍只管活动评论，不管瞬间评论。

## 决策摘要

| 项 | 选择 |
|---|---|
| 范围 | B 端 + C 端（H5/PC）一次做完 |
| 来源 | 仅 C 端提交；后台无新建、无改内容、无下架 |
| 媒体 | 图文或视频二选一：正文+1～9 图，或 1 视频+可选正文 |
| 提交资格 | 活动进行中或已结束，且报名已通过 |
| 互动资格 | 任意登录员工（演示用户）对已通过瞬间赞/评/回 |
| 审核 | 规则 `momentAuditEnabled`：开=待审核；关=直接已通过 |
| 驳回 | 必填原因；作者 C 端可见，改后再提同一条 |
| 后台动作 | 查看、通过、驳回、删除；批量通过/驳回；详情里删评论回复 |
| 评论层级 | 两层：评论 + 回复评论，不再套 |
| 数据 | 独立 moment store，B/C 共用 |
| C 端列表 | 已发布含已结束，否则结束后无法进详情投稿 |

## 功能契约

```text
功能：员工给活动投精彩瞬间；运营审核后 C 端可见；员工点赞评论回复；运营可删瞬间和评论回复
角色：员工（C 端演示用户「陈产品」）；运营（后台活动相关页，无细粒度权限）
实体：瞬间、瞬间评论、瞬间回复；活动、报名、活动类型规则只读
状态：待审核 / 已通过 / 已驳回
查询：正文、类型、状态、提交人、提交时间
操作：C 端发布/改再提/赞/评/回；后台查看/通过/驳回/删除/批量审/删评论
异常：无资格不给发布按钮；审核关直接可见；删不可恢复
验收：见文末假设/当/那么
```

## 状态流

```
提交 ──审核开──► 待审核 ──通过──► 已通过（C 端全员可见）
                 │
                 └──驳回──► 已驳回 ──改再提──► 待审核
提交 ──审核关──► 已通过
任意状态 ──删除──► 移除（C 端立刻没）
```

- 通过、删除不可逆。通过后不能改内容、不能下架。
- 改再提：同一 `id`，状态回待审核（审核关则直接已通过），更新图文/视频和时间。驳回原因保留到下一次审完；通过后清空。
- 赞只改 `likedBy`，不改状态。评论不审、即时可见。

## B 端页面

入口不变：活动管理行「更多 → 精彩瞬间管理」。Hash 仍 `#/activities/activity-moments/{id}`。

面包屑：`活动 > 活动管理 > {活动标题} > 精彩瞬间管理`  
标题：精彩瞬间管理  
副标题：审核并管理员工提交的图文和视频瞬间。

无「新建瞬间」。工具栏空。

| 操作 | 否 | 否 | 左 | 否，固定右 |

状态色：待审核 warning，已通过 success，已驳回 error。

行操作最多露出 3 个，多的进「更多」：

- 待审核：查看、通过、驳回；删除进更多
- 已通过 / 已驳回：查看、删除

通过：确认「确认通过「{正文摘要}」？」「通过后员工端可见。」  
驳回：弹窗，驳回原因必填，1～200 字。  
删除：确认「确认删除「{正文摘要}」？」「删除后员工端不再展示，评论一并删除，且无法恢复。」

### 批量

勾选后：**批量通过**、**批量驳回**、取消选择。

- 通过：只处理待审核；已通过/已驳回跳过。确认：「待审核将变为已通过，员工端可见。其他状态保持不变。」
- 驳回：只处理待审核；原因必填一条共用。

部分成功：提示成功 N、跳过原因；勾选留跳过项。全部跳过：info，勾选保留。

### 详情

抽屉，宽 `form.drawerWidth`。无后台编辑，与「查看」同一抽屉。

分组：内容（正文、类型、媒体预览）、提交信息（人、时间、状态、驳回原因）、互动（点赞数、评论树）。

待审核时抽屉主操作：通过（左）、驳回、关闭。其他状态：关闭。

评论树行内「删除」。删评论则回复一起没。确认含评论人。

## C 端页面

仍挂活动详情，不新开路由。H5 与 PC 同一套 feed/composer，壳不同。

位置：活动正文（含疗休养行程）下方。「精彩瞬间」标题；有资格时「发布瞬间」按钮。

Feed：已通过全员可见，新→旧。作者额外看见自己的待审核、已驳回。已驳回展示原因和「修改后再提」。待审核标注「审核中」。

发布：H5 Sheet / PC 弹层。类型二选一。图片：正文必填（≤200 字）+ 1～9 张本地图。视频：1 个本地视频，正文可选。提交成功 toast：审核开「已提交，待审核」；审核关「发布成功」。

无资格：不渲染发布按钮。点赞可取消。评论、回复即时出现，空内容不能发。回复展示在对应评论下。

已结束活动出现在 C 端「全部活动」列表和详情。报名中大卡逻辑不变。

## 验收场景

```text
假设公司活动开启精彩瞬间审核，陈产品报名已通过且活动已结束
当他提交图文
那么瞬间进入待审核，C 端他人不可见，作者可见「审核中」

假设运营在后台通过该瞬间
当确认通过
那么状态已通过，C 端全员可见，可赞可评可回

假设运营驳回并填写原因
当作者打开自己的瞬间
那么看到原因和「修改后再提」；改完提交后变回待审核

假设项目活动未开启审核，陈产品报名已通过且活动进行中
当他提交视频
那么直接已通过，C 端立刻可见

假设运营删除一条已通过瞬间及其下一条评论
当确认删除
那么 C 端 feed 立刻没有该瞬间；删评论则该评与回复消失

假设运营勾选 2 条待审核和 1 条已通过后批量通过
当确认
那么 2 条变已通过；提示成功 2、已通过跳过 1；勾选留那条已通过
```
