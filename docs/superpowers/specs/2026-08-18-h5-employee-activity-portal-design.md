# H5 员工活动门户重构

**日期：** 2026-08-18  
**状态：** 已确认，H5 首页「我的活动」区块已落地  
**范围：** 仅重构员工端 H5 活动首页、详情、报名及“我的报名”；PC 端与后台管理端不改。

## 背景与目标

员工从企业入口进入 H5，核心任务依次为：

1. 快速发现值得参加的活动并完成报名。
2. 按分类浏览全部已发布活动。
3. 查看自己的报名记录和活动进度。

当前首页以“报名中横滑卡 + 缩略图列表”为主，缺少员工身份感、“我的报名”入口和清晰的报名主链路；社交数字占用信息层级，但不是本场景核心任务。

## 方案

采用“员工活动门户”结构。首页围绕“发现活动 → 判断是否合适 → 查看详情 → 报名”组织信息，并在内容区顶部用“我的活动”区块承接已报名记录。

视觉不沿用现有橙色体系，改为深海军蓝与青绿组合：

- 主色：`#16324F`
- 强调色：`#14B8A6`
- 提醒色：`#F59E0B`
- 页面背景：`#F4F7FA`
- 卡片背景：`#FFFFFF`
- 卡片圆角：16px

## 路由与页面

| URL | 页面 |
|---|---|
| `#/c/h5` | 活动首页 |
| `#/c/h5/my` | 我的报名 |
| `#/c/h5/{id}` | 活动详情 |

非法 id、未发布活动或不存在活动进入统一失效态，可返回 H5 首页。PC 路由保持不变。

## 首页结构

### 1. 标准 H5 导航

- 首页、详情和“我的报名”统一使用浅色 H5 导航。
- 导航使用白色或极浅灰背景、底部分割线和深色文字。
- 左侧为 44×44px 返回按钮，中间居中显示页面标题，右侧使用等宽留白保证标题不偏移。
- 首页标题为“员工活动”，返回企业工作台；详情与“我的报名”保持现有返回关系。
- H5 导航不承载问候语、报名数量或业务快捷入口。

### 2. 我的活动

- 放在首页正文最上方、分类列表之前，不放在 H5 导航内。
- 区块标题为“我的活动”。
- 没有报名记录时展示空文案“还没有报名活动”，以及“去看看活动”按钮；点击后滚动到下方活动目录，不跳转页面。
- 有待参加记录时，最多展示 2 张紧凑卡：标题、日期、地点；点卡进入对应详情。
- 仅当待参加超过 2 条，或存在已结束/失效记录时，才在区块标题右侧显示“查看全部”，进入 `#/c/h5/my`。
- 已结束和失效记录不在首页展开；仅有这类记录时显示“查看全部”和“暂无待参加活动”。

### 3. 分类筛选

- 分类为：全部、公司活动、体检活动、疗休养活动、项目活动。
- 横向滚动，选中项使用主色或强调色。
- 首页不单独设置“正在报名”推荐区，报名状态由列表卡片展示。
- 切换分类后刷新下方活动列表。

### 5. 活动列表

- 使用纵向大图信息流卡，不再使用 96×72 缩略图密集布局。
- 卡片展示封面、标题、日期、地点、类型和报名状态。
- 置顶信息保留，但弱化为小标签。
- 点整张卡进入详情。
- 首页移除点赞、收藏、评论数字，避免干扰报名决策。
- 无数据时展示明确空态“暂无相关活动”。

## 我的报名

- 从首页“我的活动”的“查看全部”进入独立页面。
- 读取当前演示用户的全部报名记录，并按活动 id 关联当前活动数据。
- 分为“待参加”和“已结束”两组；已失效记录归入“已结束”。
- 每条展示活动标题、报名类型、日期、地点和报名状态。
- 点记录进入对应活动详情。
- 没有记录时展示空态及“去看看活动”按钮。
- 若报名关联活动已撤回或删除，记录只显示“活动已失效”和报名类型，不可进入详情；内存报名记录不保存活动标题快照。

## 活动详情

内容顺序：

1. 通栏封面。
2. 标题、类型、活动状态。
3. 核心信息卡：时间、地点、发起人、联系电话、报名限额。
4. 活动介绍富文本。
5. 疗休养活动的行程安排与额外费用规则。
6. 活动动态。
7. 底部固定报名按钮。

报名 CTA 使用现有状态规则：报名已结束、已报名、报名未开始、报名已截止或立即报名。底栏适配 `safe-area-inset-bottom`，正文留出足够底部空间。

## 报名流程

- 点“立即报名”打开底部 Sheet。
- 报名类型来自活动 `signupSettings`，去空并去重。
- 无可用报名类型时禁用确认并提示“暂不可报名”。
- 提交成功后关闭 Sheet、显示“报名成功”，详情 CTA 变为“已报名”。
- 重复提交不新增记录，提示“已报名”。
- 本轮沿用内存报名数据；刷新页面后记录清空，不宣称后端持久化。

## 组件与数据边界

- `H5ActivityShell`：H5 最大宽度、安全区、页面背景和通用返回能力。
- `H5ActivityHome`：使用标准 H5 导航，组装“我的活动”预览、分类和列表。
- `H5ActivityDetail`：详情内容、活动动态和报名入口。
- `H5MySignups`：报名记录分组与空态。
- 活动列表卡：只负责列表信息展示与打开详情。
- `clientActivity`：保留已发布筛选、分类、排序和 CTA 规则，补充分组需要的纯函数。
- `signupStore`：补充全部记录订阅 hook、当前用户记录查询和数量统计。
- `navigation` / `CEndApp`：识别 `my` 路由并挂载报名页。

不修改 PC 页面，不重构后台活动模型，不接入真实登录、权限或后端报名接口。

## 状态与错误处理

| 场景 | 表现 |
|---|---|
| 无已发布活动 | 列表显示空态 |
| 当前分类无活动 | 显示“暂无相关活动” |
| 无报名记录 | 我的报名显示引导空态 |
| 报名关联活动失效 | 记录保留，标记失效且不可进入 |
| 活动不存在或未发布 | 详情显示失效态和返回按钮 |
| 无报名类型 | Sheet 禁止确认 |
| 重复报名 | 不重复写入，显示提示 |

## 可访问性与移动端约束

- 可操作区域最小 44×44px。
- 图标按钮提供 `aria-label`。
- 筛选项使用可识别的选中状态。
- 卡片列表使用语义化列表结构。
- 正文与背景对比度不低于 4.5:1。
- 横向滑动模块支持触摸惯性和滚动吸附。
- iPhone 底部安全区不遮挡 CTA。
- 320px 至 430px 宽度下不产生横向页面滚动。

## 验收

1. `npm run build` 通过。
2. `npm run check:standards` 通过；若失败，确认不是重构引入的新问题。
3. `#/c/h5` 首屏可见浅色标准 H5 导航、“我的报名”快捷卡和分类活动列表。
4. 分类筛选正确，未发布活动不可见。
5. 活动卡可进入详情，返回行为正确。
6. 报名完成后 CTA 更新，“我的报名”数量和记录同步更新。
7. “我的报名”能区分待参加、已结束，并正确处理失效活动。
8. 详情报名 Sheet、重复报名、无类型和截止状态表现正确。
9. 320px、375px、430px 宽度下结构可用，底部 CTA 不被安全区遮挡。

## 非目标

- PC 页面重构。
- 后台活动管理改造。
- 真实员工登录、RBAC 或可见范围校验。
- 报名后端持久化、审核流或人数并发控制。
- 准确剩余名额。
- 社交功能新增或写回。
