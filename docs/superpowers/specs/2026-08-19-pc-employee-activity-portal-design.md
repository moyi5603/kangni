# PC 员工活动门户对齐

**日期：** 2026-08-19  
**状态：** 已确认，待实现  
**范围：** 仅改员工端 PC 活动首页、详情、报名弹窗表现及新增“我的报名”。H5 与后台管理端不改。  
**关联：** 任务规则对齐 `docs/superpowers/specs/2026-08-18-h5-employee-activity-portal-design.md`；本文件覆盖该文档中“PC 不改”的约束。

## 背景与目标

员工从企业入口进入 PC，核心任务与 H5 相同：

1. 快速发现值得参加的活动并完成报名。
2. 按分类浏览全部已发布活动。
3. 查看自己的报名记录和活动进度。

当前 PC 首页仍是「报名中横滑 + 全部活动网格 + 社交数字」，顶栏标题为「活动广场」，没有「我的活动 / 我的报名」，配色仍是橙色。员工在 H5 和 PC 看到两套任务结构。

## 方案

采用与 H5 相同的信息架构，保留桌面形态：

- 顶栏继续用 PC 壳，不照搬 H5 44px 导航。
- 首页：我的活动 → 发现活动；列表继续卡片网格，不改成 H5 大图竖列。
- 详情：继续左正文 + 右报名侧栏，不改成底栏 CTA。
- 报名继续用现有 PC 弹窗，不改成 H5 Sheet。
- 视觉 token 只挂在 `.c-pc-shell`：主色 `#16324F`，强调色 `#14B8A6`，提醒色 `#F59E0B`，背景 `#F4F7FA`，卡片 `#FFFFFF`，圆角 16px。

## 路由与顶栏

| URL | 页面 |
|---|---|
| `#/c/pc` | 活动首页 |
| `#/c/pc/my` | 我的报名 |
| `#/c/pc/{id}` | 活动详情 |

`my` 优先于数字 id。非法 id、未发布或不存在活动进入统一失效态，可返回 PC 首页。

顶栏三件套固定：

- 左：康尼品牌，返回企业工作台。
- 中：标题始终为「员工活动」，不再使用「活动广场」。
- 右：「手机版」，进入 `#/c/h5`。
- 顶栏不放问候语、报名数量或业务入口。

我的报名页与详情页在正文顶部提供返回 PC 首页的链接。

## 首页结构

### 我的活动

规则与 H5 相同，入口落到 PC 路由：

- 放在首页正文最上方、分类列表之前。
- 区块标题为「我的活动」。
- 没有报名记录：文案「还没有报名活动」+「去看看活动」；点击滚动到下方活动目录（`id="pc-activity-catalog"`），不跳转页面。
- 待参加最多展示 2 张紧凑卡：标题、日期、地点；点卡进入 `#/c/pc/{id}`。
- 仅当待参加超过 2 条，或存在已结束/失效记录时，标题右侧显示「查看全部」，进入 `#/c/pc/my`。
- 已结束和失效记录不在首页展开；仅有这类记录时显示「查看全部」和「暂无待参加活动」。

预览条数使用已有常量 `HOME_SIGNUP_PREVIEW_LIMIT`。

### 发现活动

- 去掉「报名中」横滑推荐区。
- 分类：全部、公司活动、体检活动、疗休养活动、项目活动。
- 选中项使用主色或强调色。
- 下方保持 PC 卡片网格。
- 卡片展示封面、标题、日期、地点、类型和报名状态；置顶弱化为小标签；整卡进入详情。
- 移除点赞、收藏、评论数字。
- 无数据时显示「暂无相关活动」。

## 我的报名

- 从首页「查看全部」进入 `#/c/pc/my`。
- 读取当前演示用户的全部报名记录，按活动 id 关联已发布活动。
- 分为「待参加」和「已结束」；已失效记录归入「已结束」。
- 每条展示活动标题、报名类型、日期、地点和报名状态。
- 有效记录进入对应 PC 详情。
- 没有记录时展示空态及「去看看活动」，回到 `#/c/pc`。
- 关联活动已撤回或删除时，只显示「活动已失效」和报名类型，不可进入详情；内存记录不保存活动标题快照。

## 活动详情

双栏：左正文，右报名侧栏。

左栏顺序：

1. 通栏封面。
2. 标题、类型、活动状态。
3. 核心信息：时间、地点、发起人、联系电话、报名限额。
4. 活动介绍富文本；若首个标题文本为「活动介绍」则去掉该标题，避免与版块重复。
5. 疗休养活动的行程安排与额外费用规则。
6. 活动动态。

右栏只放决策信息：短标题、活动状态、报名 CTA。不放社交数字。CTA 规则沿用 `signupCta`：报名已结束、已报名、报名未开始、报名已截止、立即报名。点「立即报名」打开现有 PC 弹窗。

报名流程：

- 报名类型来自 `signupSettings`，去空并去重。
- 无可用类型时禁用确认并提示「暂不可报名」。
- 提交成功后关闭弹窗、toast「报名成功」，CTA 变为「已报名」。
- 重复提交不新增记录，toast「已报名」。
- 继续使用内存报名；刷新后清空，不宣称后端持久化。

## 组件与数据边界

- `PcActivityShell`：PC 顶栏、页面背景和 token 作用域。
- `PcActivityHome`：组装「我的活动」预览、分类和网格。
- `PcActivityDetail`：左栏内容 + 右栏 CTA。
- `PcMySignups`：新增，报名记录分组与空态。
- `PcSignupModal` / `PcMomentModal`：交互形态不改，只跟随 PC token。
- `clientActivity` / `signupStore`：复用，不为 PC 再写一套分组或报名逻辑。
- `navigation` / `CEndApp` / `App`：解析 `pc/my` 并挂载报名页。`my` 对 h5、pc 都生效。

不修改 H5 组件，不重构后台活动模型，不接入真实登录、权限或后端报名接口。

## 状态与错误处理

| 场景 | 表现 |
|---|---|
| 无已发布活动 | 列表显示空态 |
| 当前分类无活动 | 显示「暂无相关活动」 |
| 无报名记录 | 首页空态引导到目录；我的报名页引导回首页 |
| 报名关联活动失效 | 记录保留，标记失效且不可进入 |
| 活动不存在或未发布 | 详情显示失效态和返回首页 |
| 无报名类型 | 弹窗禁止确认 |
| 重复报名 | 不重复写入，显示提示 |

## 可访问性与桌面约束

- 可操作区域最小 44×44px。
- 图标按钮提供 `aria-label`。
- 筛选项使用可识别的选中状态。
- 卡片使用语义化列表。
- 正文与背景对比度不低于 4.5:1。
- 1024px 及以上保持双栏详情和网格列表；变窄时侧栏可折到正文下方，但不改成 H5 底栏 CTA。
- 不产生整页横向滚动。

## 验收

1. `npm test` 与 `npx tsc -b` 通过。
2. `#/c/pc` 顶栏为「员工活动」，可见「我的活动」和「发现活动」，没有报名中横滑和社交数字。
3. `#/c/pc/my` 可打开，分组和失效态正确；返回回到 PC 首页。
4. `#/c/pc/{id}` 为双栏详情，CTA 与报名弹窗行为正确。
5. 未发布活动不可见；分类筛选正确。
6. H5 路由与页面视觉不被这次改动破坏。
7. 后台管理端不受影响。

## 非目标

- 重做 H5。
- 后台活动管理改造。
- 把 PC 改成手机窄栏或 H5 底栏 CTA。
- 真实员工登录、RBAC 或可见范围校验。
- 报名后端持久化、审核流或人数并发控制。
- 准确剩余名额。
- 社交功能新增或写回。
