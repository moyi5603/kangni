# 活动报名审批流方案

日期：2026-09-23
状态：业务已确认，并已按本文实现。

活动报名按自定义节点串行审批。每个节点三选一：指定人、本部门负责人、上级部门负责人。

员工部门是必填信息。报名人一定有主部门，不存在「报名人无部门、锚点无处可放」。

「不在」包括：离职、档案不存在、账号停用、账号冻结、离职办理中。这几种都按审批人缺失处理：节点里一个在职的人都不剩就跳过；还剩其他人就去掉不在的，其余人继续审。

## 报名记录上存什么

提交时抄一份节点表，只抄定义：顺序、指派方式、指定人名单。不抄部门负责人是谁。

记录上只留当前这一步：节点序号、当前审批人。后面的节点不落人。

活动上之后改审批流，待审核在途单的节点表副本不动。第一次报名，以及驳回后再次报名，按活动上当时的审批流抄新表。

## 什么时候查人

只查即将进入的节点，读这一轮抄下的节点表副本：

1. 报名提交：从第 1 个节点开始查
2. 当前节点有人点通过：从下一节点开始查
3. 驳回后再次报名：丢掉旧副本，按活动上当前审批流重新抄一份，从第 1 个节点查。锚点是报名人
4. 定时扫描：扫在途待审核报名。当前审批人里已有人变为不在的，按缺失规则处理；这一步一个在职的人都不剩就跳过，并继续查后面的节点。还没轮到的节点不扫。定时扫描不因调岗或卸任换人
5. 打开报名名单：重查待审核单的当前这一步。当前节点是本部门负责人或上级部门负责人，而当前审批人还在职、但已经不是按锚点查出的现任负责人时，待办换成现任负责人

同一次查找可以连跳，不需要人再点一次。部门多名负责人、同一节点多名指定人，都按或签。一个人只认主部门。

人还在职，只是调岗或不再担任该部门负责人：打开报名名单时，按上面第 5 条换成现任负责人，旧负责人不能再审。锚点不变，只换岗位上的人。多名负责人时，待办改成现在这批人。这次换人不算缺失，不发缺失通知，也不跳过节点。现任本人若不在，再按缺失规则处理。指定人节点不因调岗换人。还没轮到的节点不提前记人，进入该节点时按当时的组织重新查。

## 驳回

或签节点里任意一人驳回，整张报名驳回。同一节点上其他人的待办结束，不再等他们。

报名人可以再次报名。再次报名不沿用旧节点表：

- 丢掉这一单上的旧节点表副本
- 按活动上当前审批流重新抄一份。只抄顺序、指派方式、指定人名单，不抄部门负责人是谁
- 从第 1 个节点重新查人。上一轮已经通过的节点作废，都要再审
- 锚点改回报名人的主部门。上一轮的当前审批人、最后通过人、驳回节点序号清空，不拿来决定从哪进入
- 驳回原因留在记录上，只说明上次为什么驳回，不参与查人
- 这一轮的缺失通知和跳过日志重新记，不沿用上一轮

再驳回、再报名，仍按当时活动上的审批流重新抄，再从第 1 个节点走。

待审核的在途单不走这条。活动上改审批流，只影响还没抄表的新报名，以及驳回后的再次报名。

## 锚点

| 情况 | 下一节点「本部门 / 上级部门」按谁的部门 |
|---|---|
| 前面没有被跳过的指定人，也还没有人通过 | 报名人的主部门 |
| 有人实际点了通过 | 最后一名实际通过的人的主部门。多人节点谁先审，锚点就是谁 |
| 指定人节点因人不在被跳过，只有一人，或多人主部门相同 | 这个主部门。不用报名人，也不用上一名实际通过的人 |
| 同一指定人节点里多人都不在，主部门不同 | 这些主部门都可以审。本部门负责人取各部门负责人，上级部门负责人取各部门的上级部门负责人，或签。谁先审，之后的锚点就是谁 |
| 连续多个指定人节点都被跳过 | 用最近一个仍能读到主部门的指定人。该节点里有多个主部门时，按上一行，这些部门都可以审 |
| 指定人档案上已经没有主部门 | 退回上一名实际通过的人；他是第 1 节点、前面也没有可退回的人时，退回报名人 |

指定人节点被跳过后，负责人节点再因岗位空着被跳过：锚点不变，仍是这些指定人的主部门，直到有人实际点通过。多名部门里只有一部分负责人不在：去掉这部分，其余部门继续审，不跳过整个节点。

离职后档案主部门被改成「离职人员」等池子、已不是原部门的，暂不处理。仍按档案上当前的主部门取值。

例：节点是「指定张三 → 本部门负责人」或「指定张三 → 上级部门负责人」。张三已离职，档案主部门仍是前端组。

- 第 1 节点跳过，发缺失通知
- 本部门负责人取前端组的负责人
- 上级部门负责人取前端组的上级部门负责人

例：节点是「李四 → 指定张三 → 本部门负责人」。李四已通过，张三不在。第 3 节点按张三的主部门查，不按李四。

例：同一节点指定张三、李四，两人都不在。张三主部门前端组，负责人王五；李四主部门产品中心，负责人赵六。下一步本部门负责人由王五、赵六或签，谁先审谁通过。王五先通过，再下一步的锚点是王五的主部门。

## 查找结果

| 查到的结果 | 处理 |
|---|---|
| 有在职且不是报名人、也不是刚通过的那个人 | 写入当前审批人，停在这一步 |
| 指定人还有部分在职 | 去掉不在的人，其余人继续审。不跳过、不发缺失通知 |
| 查到的人就是报名人，或就是刚通过的那个人 | 跳过，继续查下一节点。只记日志，不发缺失通知 |
| 上级部门：主部门已经没有上级 | 跳过，继续查下一节点。只记日志，不发缺失通知 |
| 审批人不在，或部门、负责人岗位空着，或部门已删除 | 跳过，继续查下一节点，并发缺失通知。指定人被跳过时按上一节更新锚点 |
| 节点表走完 | 报名审批通过 |

被跳过的若是最后一个节点，或后面的节点也都被跳过：审批流完成，报名通过。

## 缺失通知

接收人：活动创建人、活动管理员。同一人只发一条。

一次查找里跳过多个缺失节点，合成一条消息，每个节点一行。若这次跳过导致整单通过，消息末尾加上「审批流已完成，报名已通过」。

- 指定人：`第 2 节点审批人缺失（王五已离职），该节点已自动跳过`
- 本部门：`第 3 节点「前端组」本部门负责人缺失，该节点已自动跳过`
- 上级部门：`第 4 节点「产品中心」上级部门负责人缺失，该节点已自动跳过`
- 部门没了：`第 3 节点部门不存在，负责人缺失，该节点已自动跳过`

同一人、到顶这两种跳过不发这条消息。报名人侧不发这条。中间被跳过时他仍看到审核中；整单通过后看到已通过。

## 配置

添加或编辑节点时：

- 相邻两个节点不能都是「本部门负责人」。改中间节点把前后凑成一对，同样拦住
- 「上级部门负责人」不按组织层级禁用。锚点要等上一节点通过，或指定人被跳过之后，才知道
- 节点总数上限 10
- 连续「上级部门」次数超过「组织最大层级 − 1」时只警告，仍允许保存。多出来的步，查找时会因到顶被跳过

「本部门 → 上级 → 本部门」允许。

## 场景

### 连续本部门

配置已挡住，运行时不会出现「本部门接本部门」。

仍可能查出同一个人。例如第 1 步指定李四且李四在职并通过，第 2 步本部门负责人，李四正是该部门负责人。这一步跳过，继续查第 3 步。只记日志，不发缺失通知。

第 1 步是本部门负责人，报名人自己就是该负责人：提交时跳过，接着查后面的节点，不给报名人自己生成待办。

### 上级部门加到何时

配置不封顶。封顶发生在查找时：主部门没有上级，这一步跳过，同一次查找继续看下一个节点。这是到顶，不是人缺失，不发通知。

连续上级是逐级往上。指定人夹在中间会把锚点换成这个人；这个指定人若不在，锚点用他的主部门，从该部门再往上数。

### 审批中改了节点

在途单不跟活动上的新审批流。通过之后查下一节点，查的是报名时抄下的那张表。

张三的副本是：王五 → 本部门负责人 → 上级部门负责人。王五已通过，当前审批人是李四。此时把活动改成「赵六 → 上级部门负责人」：

- 李四的待办不变
- 李四通过后，仍按张三的旧表查第 3 步，锚点是李四
- 不会改去等赵六，也不会因为新表只剩 2 步就直接通过

正在等的这一步，不因为活动改了节点类型而重算。人不在、岗位空着，走「审批人不在」。人还在职但已调岗或卸任，走下一节，不在这里换人。

### 驳回后再报名时改了节点

李四在第 2 节点驳回了张三。此时活动审批流已改成「赵六 → 上级部门负责人」。张三再次报名：

- 旧表作废
- 抄当前表：赵六 → 上级部门负责人
- 从第 1 节点查赵六，锚点是张三
- 不从上次驳回的第 2 节点进入。上一轮的王五不再算已通过

活动上的审批流若没改，再次报名仍重新抄当时那张表，并从第 1 节点重走。

### 调岗或卸任

当前节点是前端组的本部门负责人，待办在王五身上。王五调到财务，前端组现任负责人是赵六。打开报名名单后：

- 待办换成赵六，王五不能再审
- 锚点仍是原来的部门，不改成财务
- 不发缺失通知，节点不跳过

多名负责人时，待办整份换成现在这批人。赵六本人已离职，再按缺失规则跳过并发通知。

节点是指定人王五时，王五调岗后待办仍是王五。定时扫描碰到这次调岗也不换人，要等打开报名名单。

### 审批人不在

待审核在途单已经抄走的节点表，改活动审批流换不掉。驳回后再次报名不在此列，见「驳回」。

- 还没轮到的节点先不查。上一节点通过，或前面的节点在同一次查找里被跳过时，再查
- 正在等的人不在（含停用、冻结、离职办理中）：由定时扫描发现，不等到有人再次打开这张单。指定人里还有其他人在职，去掉不在的人，节点继续。一个在职的人都没有，这一步自动跳过，并通知创建人和管理员
- 本部门或上级部门负责人岗位空着、人或部门不存在：同样跳过并发通知
- 被跳过的指定人，下一步若是本部门或上级部门，按他的主部门取值，规则见「锚点」
- 被跳过的是最后一个节点，或后面的节点也都被跳过：审批流完成，报名通过。通知里写明缺失节点，并写上已通过
- 不改派、不把单子停在「审批人缺失」
