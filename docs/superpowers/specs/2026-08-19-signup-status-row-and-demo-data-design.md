# 报名卡状态行与演示数据

**日期：** 2026-08-19  
**状态：** 已确认，待实现  
**范围：** H5 / PC 首页「我的活动」预览卡、「我的报名」列表卡、C 端报名 store 的演示种子。发现活动、详情、后台管理端不改。  
**关联：** `docs/superpowers/specs/2026-08-19-signup-card-cover-thumb-design.md`

## 背景与目标

员工要在「我的活动」一眼看出活动走到哪、报名审没审。现在活动状态贴标题，审核状态「已通过」掉在报名类型下面，且演示账号默认没有报名，首页经常是空态。

## 方案

有效报名卡：标题下方并排两颗 pill——活动状态 + 审核状态。封面左侧方图保持不变。演示用户启动即带多种状态的报名记录。

## 状态行

有效卡从左到右：封面、文案列、chevron。文案列自上而下：

1. 标题（不再并排活动 pill）。
2. 状态行：`[活动状态] [审核状态]`。
3. 「我的报名」继续报名类型、日期、地点。首页预览没有报名类型，但仍有状态行 + 日期地点。

活动状态沿用现有 `StatusPill`：未开始 / 进行中 / 已结束。  
审核状态用同类 pill，文案为报名记录的 `status`：待审核 / 已通过 / 已驳回。本需求不展示已取消。

失效卡：标题「活动已失效」，不编活动状态；审核状态仍显示。报名类型保留。无封面、无 chevron。

## 颜色

挂在 `.c-h5-shell` / `.c-pc-shell`：

| 标签 | 底色 |
|---|---|
| 未开始 | `#F59E0B` |
| 进行中 | `#16324F` |
| 已结束 | `#8A99AB` |
| 待审核 | `#F59E0B` |
| 已通过 | `#14B8A6` |
| 已驳回 | `#94A3B8`，白字 |

两颗 pill 同一行、间隙 6–8px，可换行但不遮封面。

## 演示种子

`signupStore` 初始列表为演示用户 `陈产品` / `13800001111` 的固定记录，不是空数组。新 `submitSignup` 仍写入 `已通过`。

| activityId | 活动 | 活动状态来源 | 审核 |
|---|---|---|---|
| 2 | 新员工入职训练营 | 进行中 | 已通过 |
| 6 | 年度体检安排 | 未开始 | 待审核 |
| 9 | 中秋员工晚会 | 未开始 | 已通过 |
| 1 | 春季员工开放日 | 已结束 | 已驳回 |
| 3 | 线上公益讲座 | 未发布，C 端视为失效 | 待审核 |

`createdAt` 必须让 `groupClientSignups` 按时间倒序后，待参加前两条为 id 2 然后 id 6，这样首页预览能同时看到进行中+已通过、未开始+待审核。待参加超过 2 条且存在已结束/失效，首页显示「查看全部」。

`resetClientSignups()` 行为保持清空，供测试走空态。不要改成恢复种子，否则现有空态测试全坏。应用冷启动读模块初始种子即可。

`ClientSignup.status` 类型扩到至少 `'待审核' | '已通过' | '已驳回'`（可与后台 `SignupStatus` 对齐，但 C 端种子不含已取消）。

## 测试

- 不调用 `reset` 时（或显式写入种子后）：首页「我的活动」含训练营、体检标题，含进行中/已通过与未开始/待审核；切片内不含春季开放日标题。
- `resetClientSignups()` 后首页仍是「还没有报名活动」。
- 「我的报名」有效卡 HTML 在标题后出现状态行；报名类型附近不再单独出现旧的 `c-*-signup-status` 文案块（改为 pill）。失效卡含「活动已失效」和「待审核」，不含活动状态 pill 的「未开始/进行中/已结束」。
- `submitSignup` 成功记录仍是 `已通过`。
- 发现活动 / 详情现有测试继续通过。

## 不做

- 不改发现活动网格/竖列、详情侧栏、报名弹窗、后台报名审核流。
- 不 mock 已取消。
- 不把 H5 / PC 合成一套组件；状态行 markup 可各自写，class 名统一（如 `c-signup-status-row`）。
- 不把 `resetClientSignups` 改成恢复种子。
