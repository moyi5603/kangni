# 活动规则设置

**状态：** 待实现  
**日期：** 2026-08-18  
**范围：** 康尼2 活动应用「规则设置」配置页。按活动类型维护报名资格阶梯、精彩瞬间审核开关、活动审批流。本轮只保存配置，不改活动提交审批、疗休养司龄字段、C 端报名校验。

## 背景

活动左侧已有「规则设置」，当前走占位页。运营需要按活动类型配置三类组织级策略：谁能报名、瞬间要不要审、活动要不要走审批节点。

活动类型是封闭字典，与新建活动一致：公司活动、疗休养活动、体检活动、项目活动。不是可增删的业务集合，因此本页是设置页，不是搜索列表页。菜单保持现有一级五项，不把三类规则拆成子菜单。

规范依据：`build-ant-design-b2b-app` 设置页分组、高级表单底栏、Form.List 子表、按钮主左次右、标签同行 112px。

## 决策摘要

| 项 | 选择 |
|---|---|
| 页面模式 | 设置页 + 高级表单（独立页、底栏固定） |
| 分组 | 页内三 Tab：报名设置 / 精彩瞬间设置 / 审批流设置 |
| 类型维度 | 四个活动类型各一份配置，类型只读不可增删 |
| 报名规则 | 阶梯：每条 = 入职满 x 年 + 每年 x 次；空列表 = 不限；重叠取最高档 |
| 瞬间规则 | 每类型一个 Switch，默认关 |
| 审批规则 | 每类型一个 Switch，默认关；开启后串行节点 |
| 节点指派 | 二选一：指定审核人（多选，任一人过）或指定审核部门（单选，仅负责人过） |
| 保存 | 一次保存三 Tab；校验失败停在出错 Tab |
| 数据 | `features/activities` 本地 store，与分类/标签同一模式 |
| 生效范围 | 本轮不驱动活动审批、瞬间审核流、C 端报名 |

## 路由与入口

现有菜单 `activity-rules` 不变。Hash：`#/activities/activity-rules`。

`App.tsx` 该页从 `PlaceholderPage` 换成规则设置页。Tab 存在页面状态，不进 URL（设置页不是可分享筛选）。

面包屑：`活动 > 规则设置`。  
标题：规则设置。  
副标题：按活动类型配置报名资格、精彩瞬间审核和活动审批流。

## 页面结构

```
面包屑
标题 + 副标题（同一行）
Tabs：报名设置 | 精彩瞬间设置 | 审批流设置
当前 Tab 正文
底栏：保存 | 重置
```

- 底栏主操作「保存」在左，次操作「重置」在右。一个主按钮。
- 三个 Tab 共用一份表单草稿。切换 Tab 不丢未保存内容，也不触发保存。
- 离开本页（切菜单、切应用、浏览器返回）且草稿相对上次快照有改动：确认后再走。
- 「重置」恢复到上次成功保存的快照，留在当前 Tab。
- 窄屏：表单整体改为纵向标签；表格允许横向滚动；底栏仍固定可达。

## 数据模型

```text
ActivityTypeRule
  type: ActivityType
  signupLadders: SignupLadder[]     // 空 = 年限不限且次数不限
  momentAuditEnabled: boolean       // 默认 false
  approvalEnabled: boolean          // 默认 false
  approvalNodes: ApprovalNode[]     // approvalEnabled=false 时保存为空数组

SignupLadder
  minSeniorityYears: number         // 整数 ≥ 0
  annualQuota: number               // 整数 ≥ 1

ApprovalNode
  id: string
  assigneeMode: 'people' | 'department'
  reviewerIds: string[]             // people 时至少 1 人；department 时为空
  departmentId: string | undefined  // department 时必填；people 时为空
```

四个类型始终各有一条 `ActivityTypeRule`。不能删除类型行。

**阶梯匹配（纯函数，本轮页面可展示说明，运行时暂不调用）：**  
过滤 `minSeniorityYears <= 员工司龄`，取 `minSeniorityYears` 最大的一条。一条都没有则不限。

**保存时阶梯：** 按 `minSeniorityYears` 升序写入。同一 `type` 内年限不得重复。

**审批节点：** 数组顺序即串行审批顺序。开启审批时至少 1 个节点。每个节点 `assigneeMode` 为人或部门，互斥；切换方式时清空另一侧字段。

**关闭审批：** 界面隐藏节点区；草稿里节点可暂时保留，便于关掉再打开未保存前不丢。一旦保存时 `approvalEnabled === false`，该类型 `approvalNodes` 写成 `[]`。

部门负责人不在本页挑选。节点只存部门；文案写明「仅该部门负责人可通过本节点」。演示数据不需要负责人名单。

## 字段规格

桌面端标签与控件同行，标签宽 112px、不换行。占位文字不代替标签。

### Tab 1 报名设置

四个类型各一张紧凑 Card，标题为类型名。Card 内 `Form.List`。

| 字段 | 场景 | 默认值 | 数据源 | 展示／组件 | 选择方式 | 必填与校验 | 联动／特殊规则 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 入职满 | 表单 | 空 | 用户输入 | `InputNumber` + 后缀「年」 | 单值 | 该行存在则必填；整数 ≥ 0 | 与同类型其它行年限不能重复 |
| 每年报名机会 | 表单 | 空 | 用户输入 | `InputNumber` + 后缀「次」 | 单值 | 该行存在则必填；整数 ≥ 1 | 无 |

每条阶梯一张小 Card，字段单列，后缀用 `Space.Compact` + 禁用「年」「次」按钮，与活动报名设置里司龄控件一致。列表下方虚线块按钮「添加报名条件」（`dashed` + `block` + `PlusOutlined`）。每行可删除。允许删到 0 行。

0 行空态文案：「未设置，报名年限和次数不限」。

Card 副文案：「多条按入职年限匹配，取最高档。未设置则不限。」

### Tab 2 精彩瞬间设置

四行表格，无查询区、无分页、无批量。不是搜索列表页，不套四层列表结构。

| 列 | 链接 | 排序 | 对齐 | 截断 |
| --- | --- | --- | --- | --- |
| 活动类型 | 否 | 否 | 左 | 否 |
| 开启精彩瞬间审核 | 否 | 否 | 左 | 否 |

| 字段 | 场景 | 默认值 | 数据源 | 展示／组件 | 选择方式 | 必填与校验 | 联动／特殊规则 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 开启精彩瞬间审核 | 表单 | 关 | 布尔 | `Switch`（开/关） | 单选 | 否 | 关 = 瞬间无需审；开 = 预留给瞬间审核流。本轮只存值 |

无行操作列。Switch 即编辑器。

### Tab 3 审批流设置

四个类型各一张紧凑 Card，标题为类型名。

| 字段 | 场景 | 默认值 | 数据源 | 展示／组件 | 选择方式 | 必填与校验 | 联动／特殊规则 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 开启审批 | 表单 | 关 | 布尔 | `Switch` | 单选 | 否 | 关：隐藏节点区。保存时若仍为关，节点写成空数组 |
| 指派方式 | 表单 | 指定审核人 | 固定两项 | `Radio.Group` | 单选 | 开启审批后每节点必填 | 切换时清空审核人与审核部门 |
| 审核人 | 表单 | 空 | `orgPeoplePickerTree` | `TreeSelect` | 多选 | 指派方式=指定审核人时至少 1 人 | 任一人通过即完成本节点。树空时不可提交空值 |
| 审核部门 | 表单 | 空 | `orgDepartmentTree` | `TreeSelect` | 单选 | 指派方式=指定审核部门时必填 | 仅该部门负责人可通过。树空时不可提交空值 |

节点区仅在「开启审批」为开时显示。每个节点一张小 Card，标题「第 N 节点」。虚线块按钮「添加审批节点」。节点可删；开启审批时保存前至少保留 1 个。数组顺序即审批顺序，不提供拖拽。添加追加在末尾。

审核人帮助文本：「可多选，任意一人通过即完成本节点。」  
审核部门帮助文本：「单选。仅该部门负责人通过即完成本节点。」

## 交互与反馈

| 事件 | 行为 |
| --- | --- |
| 保存成功 | Message：「规则已保存」。更新快照，底栏结束 loading |
| 保存校验失败 | 切到第一个出错 Tab，滚动并聚焦第一处错误字段。不写 store |
| 同年限重复 | 后一行「入职满」报错：「同一类型入职年限不能重复」 |
| 开启审批且 0 节点 | 该类型节点区报错：「请至少添加一个审批节点」 |
| 保存中 | 保存、重置禁用并 loading，防连点 |
| 重置 | 草稿回到上次成功快照。无未保存改动时重置仍可用，结果不变 |
| 未保存离开 | `Modal.confirm`，标题含「规则设置」，说明未保存改动将丢失。主按钮在左 |

按钮组一律主左次右。弹窗确认若用 antd `Modal`，必须自定义 Footer，不能用默认 Ok 在右。

## 演示数据

首次进入写入四条默认规则（全关、报名空列表、节点空）。另给运营可看的示例（仍可改可重置到「上次保存」，不是系统只读）：

- 疗休养活动：阶梯 满 1 年 / 每年 1 次，满 3 年 / 每年 2 次；瞬间审核关；审批关
- 公司活动：报名空（不限）；瞬间审核开；审批开；节点 1 指定审核人（张悦、李明）；节点 2 指定审核部门（人力资源）
- 体检活动、项目活动：全部默认

## 明确不改

- 活动新建/编辑里的报名设置、疗休养司龄、是否审核
- 活动列表「提交审批」「发布」判定
- 精彩瞬间管理列表的审核动作
- C 端报名资格
- 左侧菜单信息架构

## 异常与空态

| 情况 | 表现 |
| --- | --- |
| 某类型 0 条报名条件 | 合法空态文案，允许保存 |
| 人员树/部门树无数据 | TreeSelect 空态；对应必填节点不能保存 |
| 本地读取失败 | 页内错误说明 + 重试；不闪空整个后台壳 |
| 无权限 | 本轮原型不接权限模型，进入即可编辑 |

## 测试重点

- 纯函数：空列表不限、最高档匹配、年限去重、关闭审批保存后节点为空
- 页面：三 Tab 草稿不丢、保存校验切 Tab、未保存离开、重置
- 规范：`tsc`、`python3 scripts/check_ui_conformance.py --root .`、改动文件 `antd lint`

## 规范对照

- 设置页按影响范围分组（三类策略 × 活动类型）
- 非集合对象，不套搜索列表四层结构
- 子表 + 树选择 = 高级表单，独立页 + 底栏
- 添加子项用虚线块按钮，与活动报名设置一致
- 精彩瞬间结构均一、无子表，用表内 Switch，不用四张只有一个开关的 Card
- 不因本页改应用骨架或菜单深度
