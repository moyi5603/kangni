# 规则设置：新建活动可选类型

**状态：** 待实现  
**日期：** 2026-08-21  
**范围：** 活动应用「规则设置」增加第四 Tab，控制新建活动时哪些类型可选。新建表单隐藏已关类型；编辑可改到仍开放类型，当前已关类型只读保留。列表筛、详情、C 端、报名/瞬间/审批配置不改。

## 背景

活动类型是封闭四字字典：公司活动、疗休养活动、体检活动、项目活动。规则页按类型配报名阶梯、瞬间审核、审批流，但不能关掉某类型的新建入口。运营需要临时停用某类型时，新建活动 Radio 仍四个全在。

规范依据：`build-ant-design-b2b-app` 设置页、横向表单、按钮主左次右。对照：规则页「精彩瞬间设置」按类型 Switch 表。

## 决策摘要

| 项 | 选择 |
|---|---|
| 入口 | 规则设置第四 Tab「类型设置」，在审批流后面 |
| 控件 | 表：活动类型（只读）+ 允许新建 Switch |
| 默认 | 四个 `createEnabled: true` |
| 保存约束 | 至少开放 1 个；失败停在该 Tab |
| 新建 | 已关类型不出现；默认第一个开放类型 |
| 编辑 | 只能改到开放类型；当前已关则该项 `disabled` 仍显示 |
| 列表 / 详情 / C 端 | 四类型仍全显示 |
| 关类型 | 不删该类型报名/瞬间/审批配置 |

## 页面结构 — 类型设置 Tab

```
Tabs：报名设置 | 精彩瞬间设置 | 审批流设置 | 类型设置
类型设置：
  Card > Table
    活动类型 | 允许新建
底栏仍：保存 | 重置（三 Tab 共用，现有行为）
```

- 四行，顺序与 `activityTypes` 一致，不能增删行。
- Switch：`checkedChildren="开"` / `unCheckedChildren="关"`，`aria-label` 含类型名，例如「允许新建公司活动」。
- 保存时零个开放：校验失败，切到「类型设置」，文案「至少开放一种活动类型」。
- 副标题改为：`按活动类型配置报名资格、精彩瞬间审核、活动审批流和新建可选类型。配置后立即生效。`

## 数据模型

`ActivityTypeRule` 增加：

```text
createEnabled: boolean   // 默认 true；缺字段当 true
```

四个类型始终各有一条规则。`prepareRulesForSave` 写出 `createEnabled: current.createEnabled !== false`。

`RULES_MOCK_VERSION` 从 1 升到 2，触发本地 mock 重载种子（全开）。种子里显式写 `createEnabled: true`。

活动实体不加字段。是否可新建只读规则 store。

## 新建 / 编辑表单

纯函数（放 `rules.ts` 或紧邻 helper）：

```text
listCreatableTypes(rules, currentType?: ActivityType) → Radio options
  新建：createEnabled 为 true 的类型
  编辑：开放类型可选；若 currentType 已关，仍加入该项且 disabled: true
```

- 新建 `initialValues.type`：第一个开放类型，不再写死「公司活动」。
- 新建可选列表为空（规则坏数据）：类型项禁用，保存前校验「暂无开放的活动类型，请先在规则设置中开放」。
- 编辑保存仍写原 `type` 字段；不能提交已关且非当前的类型（Radio 根本没有）。
- 疗休养联动（行程/额外费用/报名司龄）仍跟所选 `type` 走，与是否开放无关。

## 查询与展示

活动列表类型筛、详情「类型」字段继续用完整 `activityTypes`。已关类型的历史活动仍出现在列表和 C 端。

## 测试与验收

无现成 `rules` 单测，本轮补纯函数测试：

1. 全开 → 新建四个都在
2. 关掉「项目活动」→ 新建不含它；编辑当前是项目活动 → 选项在且 disabled
3. 全关 → 新建列表空；保存规则校验失败

改完跑活动相关单测 + `check_ui_conformance.py`。

可观察：

- 规则页第四 Tab 能开关；全关不能保存
- 关掉体检后，新建活动看不到体检；编辑一条体检活动仍看到体检（灰）且能改成公司活动
- 列表仍能按体检筛选到旧数据
