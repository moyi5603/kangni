# 报名 Tab 场次概况与筛选

> **已废止（2026-08-31）**：改为人表 + 场次列 + 可搜索场次筛，见 `2026-08-31-signup-tab-session-filter-design.md`。下文仅作历史记录。

日期：2026-08-31  
状态：已确认  
范围：管理后台「活动」「兴趣圈」活动详情的 **报名 Tab**。仅周期活动、系列活动。单次活动报名 Tab 保持现状（无场次概况、无场次筛）。C 端、添加人员/导入、Header 不改。

## 背景

报名 Tab 现在是人表。周期/系列多一列「场次」，只说明此人报了哪场，看不到**每场占用**。兴趣圈一条报名一个 `sessionId`；活动应用答案「场次」可多选。

## 结构

周期 / 系列（`needsSessionPick`）：

```
查询区（现有条件 + 场次）
场次概况表
人员表（现有列 + 按场次过滤）
```

单次：查询无场次、无概况表、人员表无场次列（与现网一致）。

## 查询

周期/系列增加 **场次** Select，放在现有条件之后：

- 选项：`全部场次` + 各场 `第 n 场 YYYY-MM-DD HH:mm ~ HH:mm`（时间按该场 `startAt`/`endAt`）
- 默认 `全部场次`
- 收起态仍按现有「前三项」规则；场次在展开后出现（不挤掉姓名/状态）

点查询才生效（与现有 SearchPanel 一致）。兴趣圈报名 Tab 目前点查询无 success toast，保持各页原样。

## 场次概况表

无独立 Card 标题。表格在查询区与人员工具栏之间。

列（从左到右）：

| 列 | 活动应用 | 兴趣圈 |
|---|---|---|
| 场次 | `第 n 场` | 同左 |
| 活动时间 | `startAt ~ endAt` | 同左 |
| 状态 | 由场次时间与活动终止推导：未开始 / 进行中 / 已结束 / 已取消 | 用 `session.status` 映射到同一套中文（upcoming→未开始，ongoing→进行中，ended→已结束，cancelled→已取消） |
| 报名人数 | 占该场名额的人数：报名状态为待审核或已通过，且所选场次包含该 `session.id` | `status` 为待审核或已通过且 `sessionId === session.id` |
| 名额 | 每场上限：`signupSettings` 第一条 `limit`；`limit` 空或 0 显示 `—` | `session.capacity`；空或 0 显示 `—` |
| 待审核 | 该场待审核人数 | 同口径（有 `status` 即统计，不因名单暂无审核按钮而隐藏） |

规则：

- 行键 `session.id`。顺序与活动 `sessions` 数组一致。
- 无操作列。
- 点击行：把查询草稿和已生效查询的场次都设为该场，并刷新人员表（等同选了该场再查）。当前选中场次行可用 `rowClassName` 高亮。
- 再点已选中行：回到 `全部场次`。
- 分页：沿用 `b2bStandards.table`（默认 20）。工具栏左侧 `共 N 场`。
- 空：`暂无场次`（种子不应出现；防御）。

一人报多场（仅活动应用）：在**每一场**的报名人数 / 待审核里各计 1 次，不拆人员表行。

已取消、已驳回不占「报名人数」。

## 人员表

过滤：

- `全部场次`：现有全部报名行。
- 指定场次：只保留报了该场的人。活动用 `parseSessionIds(answers['场次'])` 包含该 id；兴趣圈用 `sessionId`。

列：

- 活动：现有列不变（姓名、部门、场次、收集信息、状态、报名时间、签到、操作）。筛了单场时「场次」列仍可显示完整已选场次文案，不强行只显示当前场。
- 兴趣圈：现有列不变。现网无状态/操作则本次不加审核操作。

分页、批量、导出、添加、导入：仍作用于**当前人员表筛选结果**。导出含场次列（活动现有导出已带场次则沿用）。

## 实现约束

- 抽出纯函数统计每场人数（活动、兴趣圈可各一份或共享 sessionId 集合），单测覆盖：多选场次重复计入每场、驳回不占额、单次活动不生成概况行。
- 不改 C 端报名、不改添加人员是否选场次、不改 Header 指标口径（Header 仍是活动总人数）。
- 兴趣圈概况「报名人数」以名单实时统计为准；与 `session.signedCount` 不一致时以名单为准（原型可顺带校正展示，不强制写回 store）。

## 验收

1. 单次活动报名 Tab：无场次筛、无概况表。
2. 周期/系列：概况表场次数 = `sessions.length`；点某场后人表只含该场。
3. 活动应用一人报两场：两场「报名人数」各 +1，全部场次人表仍一行。
4. 待审核计入「待审核」和「报名人数」；已驳回两者都不计。
5. 兴趣圈 101 等多场种子：概况能翻页；点无报名的场次人表为空。
6. 现有报名 Tab 单测按新 DOM 更新（概况表头、场次筛）。
