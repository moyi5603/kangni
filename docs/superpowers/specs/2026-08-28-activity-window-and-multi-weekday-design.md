# 活动时间窗口与周期多周几

日期：2026-08-28

## 目标

活动应用与兴趣小组应用（B 端表单、兴趣小组 C 端创建活动）统一：

1. **活动时间**是整场活动的起止窗口，精确到分，放在举办方式上方。取消「周期起止」。
2. 周期活动可复选多个周几；每个周几各自填当日时段（如周二 14:00–16:00、周三 19:00–21:00）。
3. 周期按窗口生成场次：整场落在窗口内才生成，越界不生成，到窗口结束即停。
4. 系列手填场次必须完全落在活动时间内，否则拦截保存。

## 不做什么

- 跨日时段（结束钟点早于开始钟点）
- 改报名时间与活动窗口的相对校验（沿用现有报名规则）
- 编辑态放开举办方式 / 周几规则（仍不可改举办方式；周几与各日时段编辑锁定，与现网「编辑不可改周几」一致）
- 用首末场覆盖活动 `startAt` / `endAt`

## 表单顺序

地点、发起人等现有字段之后：

1. **活动时间**（RangePicker，`YYYY-MM-DD HH:mm`，所有举办方式必填）
2. **举办方式**（单次 / 周期 / 系列）
3. 按类型：
   - 单次：报名时间、报名总人数。不再另填一场时间；活动时间即该场。
   - 周期：复选周一～周日；每个勾选日一行开始/结束钟点。去掉「周期起止」「每日时段」单组、「重复周几」单选。
   - 系列：手填至少 2 场；每场须完全落在活动时间内。
4. 周期/系列：现有「每场人数上限 / 报名开始 / 开场前 N 小时」不变。

## 数据

- `startAt` / `endAt`：用户填写的活动窗口，精确到分。列表、详情、C 端「活动时间」读这对字段，不用 `syncSessionBounds` 回写。
- 周期：`repeatRules: { weekday: 1–7, timeStart: HH:mm, timeEnd: HH:mm }[]`。至少一个周几，同一周几不重复。
- 删除表单与主路径对 `cycleStart` / `cycleEnd` / 单一 `repeatWeekday` + 一对 `timeStart`/`timeEnd` 的依赖。读取旧数据时若仅有旧字段，折成一条 `repeatRules`。
- 单次：`sessions` 仍可同步为等于窗口的一场（签到等沿用）。
- 周期生成结果写入 `sessions`。

## 生成与校验

- 从窗口开始日扫到结束日。命中某条 rule 的周几时，拼当天 `timeStart–timeEnd`。
- **整场**开始、结束都 `>= startAt` 且 `<= endAt` 才入列，否则丢弃。
- 周期保存时 `sessions.length === 0` →「该活动时间内没有可生成的场次」。
- 周期未选周几 →「请选择重复的周几」；某日时段缺或结束不晚于开始 → 对应日时段错误。
- 系列第 N 场未完全落在窗口 →「第 N 场必须完全落在活动时间内」。仍至少 2 场。
- 未填活动时间 →「请选择活动时间」。

## 展示

- B 端列表/详情「活动时间」：`{startAt} ~ {endAt}`；周期/系列可附 ` · 共 n 场`。不再展示周期起止文案。
- C 端周期短摘要：`每周二、周三 · N场`（勾选日按周一到周日排序）。

## 范围

- `src/features/activities/` 模型、表单、列表展示
- `src/features/interest-groups/` 活动模型、表单、详情/列表
- `src/features/c-end/activities` 周期短摘要
- `src/features/c-end/interest-groups/h5` 创建活动表单与顺序测试

## 验收

- 创建周期：勾周二、周三，各填不同时段，窗口内两天各生成对应钟点的场次；窗口末日钟点不够的那场不出现。
- 系列：场次超出窗口不能保存。
- 单次：活动时间在举办方式上方，即该场时间。
- 兴趣小组 B 端与 C 端创建活动同一套规则。
