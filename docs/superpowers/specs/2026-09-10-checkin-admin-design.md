# 打卡后台（文化打卡 + 技能大赛）+ 抽奖次数来源

**日期：** 2026-09-10  
**规范：** `build-ant-design-b2b-app`（列表四层、高级表单独立页、主操作在左）  
**范围：** B 端「打卡」应用做成主题配置 + 记录查询；「抽奖」表单增加次数获取途径。不做 C 端打卡页、参与范围、补卡、审核、图文打卡。

## 背景

打卡已有独立应用，目前列表弹窗只能配主题名和起止时间。文化打卡需要标签、连续打卡勋章；技能大赛需要积分；抽奖需要把打卡（以及登录、初始次数）当成次数来源。三套需求合成一套后台，用「所属应用」区分业务，不复制两套 CRUD。

## 决策

| 项 | 选择 |
|---|---|
| 后台入口 | 独立「打卡」应用。文化打卡、技能大赛只跳转列表并预填所属应用 |
| 菜单 | 仍一个一级「打卡管理」。新建/编辑/详情隐藏页，侧栏高亮打卡管理 |
| 奖励模型 | 主题上多条自定义规则，不按应用绑死奖品种类 |
| 奖励种类 | 勋章、积分、抽奖次数，一条规则可多选 |
| 触发 | 每次打卡 / 连续满 x 天 / 累计满 y 次 |
| 频次 | 同一主题、同一人、每个自然日最多 1 次 |
| 连续 | 按自然日。漏一天连续清零。累计次数不清零 |
| 发放次数 | 每条规则自选「仅一次 / 可重复」 |
| 打卡内容 | 点一下即成功。记录只有人、时间、主题 |
| 抽奖次数归属 | 打卡不绑抽奖。抽奖活动勾选关联打卡主题后才入账 |
| 抽奖获取途径 | 三个独立开关可叠加：每人初始、每日登录、打卡。至少开 1 个开关 |
| 抽奖消耗 | 沿用现有每天次数上限、可选活动期总次数 |
| 改规则 | 进行中可改，只影响之后打卡。已发奖不追回、不补发 |
| 登录口径 | 进入该抽奖 C 端页的当日首次，记一次每日登录发放 |
| 自然日 | 东八区 0 点切日 |
| 勋章素材 | 复用活动勋章库（选库或上传进库） |
| 权限 | 本轮不加 |

## 信息架构

打卡应用：

| 顺序 | key | 说明 |
|---|---|---|
| 1 | `checkin-list` | 打卡管理列表（默认页） |
| 隐藏 | `checkin-create` | 新建主题 |
| 隐藏 | `checkin-edit` | 编辑主题 |
| 隐藏 | `checkin-detail` | 详情：打卡记录 / 获奖记录 |

Hash：`#/checkin/checkin-list`、`#/checkin/checkin-create`、`#/checkin/checkin-edit/:id`、`#/checkin/checkin-detail/:id`。

抽奖应用：仍「抽奖管理」+ 原有新建/编辑/详情。编辑页「抽奖机会」拆成获取途径 + 消耗上限。

业务应用跳转：文化打卡 / 技能大赛打开 `#/checkin/checkin-list?app=culture` 或 `app=skills-contest`，列表筛所属应用。

## 领域模型

### 打卡主题

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | number | 是 | |
| title | string | 是 | 同所属应用内不重名 |
| ownerApp | `culture` \| `skills-contest` | 是 | 文化打卡 / 技能大赛 |
| tags | string[] | 否 | |
| startAt | datetime | 是 | |
| endAt | datetime | 是 | ≥ startAt |
| rules | RewardRule[] | 否 | 空 = 只记打卡不发奖 |

状态不落库，相对 now：`now < startAt` 未开始；`startAt ≤ now ≤ endAt` 进行中；`now > endAt` 已结束。

### 奖励规则

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主题内唯一 |
| trigger | `each` \| `streak` \| `total` | 每次 / 连续满 x 天 / 累计满 y 次 |
| streakDays | number | trigger=streak 时 ≥1 |
| totalTimes | number | trigger=total 时 ≥1 |
| enableMedal | boolean | |
| medalId | string | 勾选勋章必填 |
| enablePoints | boolean | |
| points | number | 勾选积分时 ≥1 |
| enableLotteryChance | boolean | |
| lotteryChance | number | 勾选次数时 ≥1 |
| repeat | `once` \| `repeat` | |

至少开启一种奖励。

### 打卡记录

同一 `themeId + userId + 自然日` 唯一。字段：user、department、account、checkedAt。

### 获奖记录

一次达标可多行（多规则或多奖种拆行）。字段：user、department、rewardKind（勋章/积分/抽奖次数）、content、ruleSummary、grantedAt、status（成功/失败可重试）。

抽奖次数行只表示打卡侧发出。入账、消耗在抽奖账户。

## 列表

结构：`ListPageHeading` → `SearchPanel` → `ListTableCard`。

副标题：`配置打卡主题、奖励规则，并查看打卡与获奖记录。`

查询：主题名称、所属应用、状态；展开：起止时间。从业务应用带入时所属应用预填，可改回全部。

列：主题名称（进详情）、所属应用、标签、起止时间、状态、打卡人数（去重）、操作（编辑、删除）。

删除：有打卡或获奖记录禁止删，提示先结束主题。进行中可删仅当零记录。抽奖已关联该主题时禁止删，须先在抽奖侧取消关联。

主操作：新建打卡。

## 主题表单

独立高级表单，两张卡：基础信息、奖励规则。

基础信息：所属应用、主题名称、标签、开始、结束。不配参与范围、不配图文。

奖励规则：可增删行。0 行合法。行内触发条件、奖励多选、发放方式。勋章：勋章库 Select 或上传（上传进库）。积分、抽奖次数为数字。

抽奖次数不选手动绑定哪场抽奖。表单项说明：由抽奖活动反向关联后才会入账；未关联时打卡仍记获奖，但次数不会进入任何抽奖。

已结束主题进入编辑：整表只读，或编辑入口禁用。进行中可改规则，文案写明只影响之后打卡。

## 主题详情

页头：主题名、所属应用、状态、起止、打卡人数。编辑（已结束禁用）、返回列表。

### Tab：打卡记录

列：姓名、部门、工号/账号、打卡时间。筛：姓名、部门、日期。导出 CSV。空态：还没有打卡记录。

同日第二次提交：拒绝「今日已打卡」，不写记录、不跑规则。

### Tab：获奖记录

列：姓名、部门、奖励类型、内容、触发规则摘要、发放时间。筛：姓名、奖励类型、日期。空态：还没有获奖记录。

「仅一次」已发过：再达标只打卡成功，不新增获奖行。可重复：每达标一行。

## 发奖计算（打卡提交时）

1. 校验主题进行中、当日未打卡。写打卡记录。
2. 更新该人连续天数、累计次数（连续按自然日，断签清零）。
3. 逐条规则判断是否达标：
   - `each`：本次即达标
   - `streak`：连续天数 ≥ x
   - `total`：累计次数 ≥ y
4. `once` 且该规则该奖种已成功发过：跳过该奖种。
5. 发积分 / 写勋章 / 记抽奖次数发出。次数入账：找出所有「进行中、未停用、次数途径勾了本主题」的抽奖，每场 +N。无关联：获奖行成功但 content 注明未入账。关联场已结束或停用：不入账，获奖行成功并注明目标抽奖不可用。
6. 积分或勋章账户失败：打卡记录保留；获奖行失败，可重试。不回滚打卡。

## 抽奖：次数获取与消耗

「抽奖机会」卡拆两段。

### 获取途径（可叠加，至少 1 项）

| 途径 | 配置 | 入账时机 |
|---|---|---|
| 每人初始 | 开关 + x≥1 | 该人第一次进入该抽奖时发一次 |
| 每日登录 | 开关 + 每天 +n，默认 1 | 该抽奖页当日首次进入 |
| 打卡 | 开关 + 多选打卡主题（开则至少选 1 个） | 关联主题按规则发出次数时 |

一个主题可被多场抽奖勾选：一次发放给每场各入账 N。

### 消耗上限（沿用）

- 每人每天最多抽 M 次（现 `dailyChance`）
- 可选活动期间总次数

抽一次：钱包 −1，且不得突破 M 和总次数。钱包为 0 或触达上限：不能抽。

### 存量

原「每人每天次数 = N」迁移为：每日登录每天 +N，消耗上限 M=N。总次数开关保持原值。

## 异常

| 场景 | 处理 |
|---|---|
| 未开始/已结束打卡 | 拒绝 |
| 同日二次打卡 | 拒绝，列表不双写 |
| 漏签 | 连续清零，累计保留 |
| 进行中改规则 | 向后生效，已发不追不补 |
| 已结束改主题 | 禁止 |
| 删除有记录主题 | 禁止 |
| 删除已被抽奖关联的主题 | 禁止，先解绑 |
| 勋章仅一次已获得 | 打卡成功，不发勋章 |
| 发奖失败 | 打卡成功，获奖失败可重试 |
| 抽奖停用/结束 | 打卡仍记 +N；该场不入账 |
| 获取途径全关 | 表单不通过 |

## 非目标

- C 端打卡与抽奖页改版（登录发放在抽奖 C 端需要后续接口，本 spec 只定口径）
- 参与人员范围、补卡、管理员代打、图文/定位
- 积分商户、勋章墙独立菜单
- 打卡侧次数核销、跨主题排行榜

## 验收要点

1. 打卡列表可按所属应用筛选；从技能大赛入口进入时默认技能大赛。
2. 主题可配多条规则：连续勋章仅一次 + 每次积分可重复，同时生效。
3. 一人一天只能打卡成功一次。
4. 漏一天后连续勋章进度清零，累计规则仍可继续累加。
5. 详情能分别导出打卡记录和获奖记录。
6. 抽奖可同时开初始次数、每日登录、关联打卡；未关联主题的次数发出不进入该抽奖钱包。
7. 现有每天次数字段迁移后，未改配置的抽奖日消耗上限与登录发放一致。
